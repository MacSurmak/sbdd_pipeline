# SBDD HPC Cluster Orchestrator (Nextflow DSL2 + Slurm)

Масштабируемый, модульный вычислительный пайплайн для молекулярного моделирования и дизайна лекарственных соединений (Structure-Based Drug Design, SBDD) на базе HPC-кластера под управлением Slurm и оркестрации Nextflow DSL2.

---

## 2. Что сделано (ключевые отличия от старого пайплайна)

1. **Полная смена парадигмы на HPC Slurm**:
   - Никаких локальных монолитных bash-скриптов и ручного управления процессами.
   - Все расчеты оркестрируются через **Nextflow DSL2** и выполняются через Slurm-очереди (`main`, `urgent`).
   - Распараллеливание докинга и реплик молекулярной динамики по GPU-узлам кластера.
2. **Чистая модульная архитектура без костылей**:
   - Schrödinger, GNINA, PPM 3.0 и AmberTools/GROMACS полностью изолированы друг от друга.
   - Каждый инструмент выполняется в своем окружении/контейнере Apptainer. Системные пути не пробрасываются в чужие контейнеры.
3. **Надежное хранение и автоматическая очистка**:
   - Все тяжелые промежуточные файлы хранятся на быстром NFS-диске `/shared/work/<project_name>`.
   - Финальные артефакты (структуры, траектории, таблицы) публикуются в чистовые директории проекта (`docking/`, `md/`, `reports/`).
   - По завершении расчетной сессии scratch-директория очищается автоматически.
4. **Запуск из любой точки (`-resume`)**:
   - Благодаря расчету контрольных сумм в Nextflow, сбой любого узла или добавление новых соединений не требует перезапуска с нуля — расчет продолжается ровно с места остановки.
5. **Атомарные конфигурационные файлы**:
   - Настройки разделены на независимые файлы: `gnina.yaml`, `glide.yaml`, `gromacs.yaml`, `project.yaml`.
6. **Единый CLI-инструмент `sbdd`**:
   - Управление проектом через удобный интерфейс в терминале.

## 3. Сценарии работы и команды запуска

### Сценарий A: Инициализация нового проекта
Создает структуру каталогов проекта и генерирует чистые шаблоны параметров:
```bash
sbdd init --name kinase_target
cd kinase_target
```
В каталоге появятся:
- `project.yaml` — базовые пути (рецептор, лиганд, мембрана: true/false).
- `configs/gnina.yaml` — параметры GNINA (exhaustiveness, cnn_scoring, batch_size).
- `configs/glide.yaml` — параметры Glide (precision, ligand_charges).
- `configs/gromacs.yaml` — параметры MD (temperature, n_replicates, chunk_ns).

### Сценарий B: Подготовка белка и лигандов (`prepare`)
Выполняет подготовку структуры (PrepWizard или PDBFixer), расчет положения в мембране (PPM 3.0) и подготовку лигандов:
```bash
sbdd prepare
```

### Сценарий C: Виртуальный скрининг (`screen`)
Разбивает библиотеку молекул на чанки и распределяет задачи докинга по GPU/CPU воркерам Slurm:
```bash
# Скрининг с помощью GNINA (GPU)
sbdd screen --engine gnina

# Либо с помощью Glide (CPU)
sbdd screen --engine glide
```
Результаты автоматически склеиваются в `docking/<project>_docked_all.sdf`, а скоры агрегируются в `reports/ranking.csv`.

### Сценарий D: Чанковая молекулярная динамика (`dynamics`)
Проводит сборку системы в явном растворителе/мембране, параметризацию в GAFF2, деклэш, равновесие и $N$ независимых реплик чанковой MD (например, 6 чанков по 10 нс = 60 нс на реплику):
```bash
sbdd dynamics --replicates 3
```
Каждый чанк генерирует чекпоинт `.cpt`, позволяя безопасно переживать лимиты времени Slurm и вытеснение задач.

### Сценарий E: Сквозной конвейер (`run`)
Выполняет полный цикл от исходных файлов до пост-анализа и итогового рейтинга:
```bash
sbdd run
```

## 4. Автоматизированное тестирование

Для быстрой проверки пайплайна без тяжелых вычислений реализована 3-уровневая система тестов:

### Уровень 1: Модульные тесты Python (Tier 1)
Проверяет математику, парсеры, форматирование GRO/TOP и RDKit:
```bash
/home/user/miniforge3/envs/sbdd_cluster_env/bin/pytest tests/unit
```
*Время выполнения: ~5 секунд. Результат: 9/9 тестов passed.*

### Уровень 2: Валидация DAG Nextflow (Tier 2)
Проверяет целостность графа потоков данных всех 4 подпайплайнов через `-stub`:
```bash
bash tests/test_workflows_stub.sh
```
*Время выполнения: ~1.5 минуты. Результат: 4/4 DAGs passed (все 50 процессов).*

### Уровень 3: Интеграционный Smoke-тест на Slurm (Tier 3)
Реальный запуск микро-расчета через Slurm на GPU-воркере с использованием Apptainer:
```bash
bash tests/cluster_smoke/run_smoke_test.sh
```
*Время выполнения: ~35 секунд. Результат: реальный расчет на GPU-ноде, публикация `ranking.csv` и автоочистка scratch.*

## 5. Точки роста и перспективы развития

1. **Интерактивный HTML-отчет (MultiQC / Streamlit)**:
   - Встроить автоматическую генерацию HTML-отчета с интерактивными графиками RMSD/RMSF, графиками кластеризации и 3D-просмотром связывания лиганда (NGL Viewer / Mol*).

3. **Автоматический переход от скрининга к MD (Active Learning / Auto-Top)**:
   - Добавить в `main.nf` автоматический отбор лучших топ-$K$ лигандов из `ranking.csv` и прямую передачу их в подпайплайн `dynamics.nf` без ручного вмешательства человека.
4. **Оптимизация упаковки мембраны**:
   - Интеграция MemProtMD / insane.py в качестве быстрой альтернативы Packmol-Memgen для стандартных липидных бислоев.
